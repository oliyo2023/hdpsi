# 商品图片表设计文档

## 概述

本文档描述了商品图片管理系统的数据库表设计，用于存储和管理服装商品的多张图片。

## 表结构

### product_images 表

商品图片表用于存储商品的多张图片信息，支持图片排序和软删除功能。

#### 字段说明

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|----------|------|--------|---------|
| id | INTEGER | PRIMARY KEY, AUTOINCREMENT | - | 图片唯一标识符 |
| product_id | INTEGER | NOT NULL, FOREIGN KEY | - | 关联的商品ID |
| url | VARCHAR(255) | NOT NULL | - | 图片存储路径/URL |
| sort | INTEGER | - | 0 | 图片排序顺序，数值越小越靠前 |
| created_at | DATETIME | - | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | - | CURRENT_TIMESTAMP | 更新时间 |
| deleted_at | DATETIME | NULL | NULL | 软删除时间，NULL表示未删除 |

#### 外键关系

- `product_id` 外键关联 `products.id`，级联删除
- 当商品被删除时，相关的图片记录也会被自动删除

#### 索引设计

为了提高查询性能，创建了以下索引：

1. **idx_product_images_product_id**: 商品ID索引
   - 用于快速查询指定商品的所有图片
   
2. **idx_product_images_sort**: 排序字段索引
   - 用于按排序顺序查询图片
   
3. **idx_product_images_deleted_at**: 软删除字段索引
   - 用于快速过滤已删除的记录
   
4. **idx_product_images_product_sort**: 复合索引 (product_id, sort)
   - 用于按商品ID和排序顺序的组合查询，这是最常用的查询模式

## 数据模型关系

```
products (1) -----> (N) product_images
```

- 一个商品可以有多张图片
- 每张图片只能属于一个商品
- 图片按 `sort` 字段排序显示

## 业务逻辑

### 图片排序

- 使用 `sort` 字段控制图片显示顺序
- 数值越小的图片越靠前显示
- 相同 `sort` 值的图片按创建时间排序
- 新上传的图片默认 `sort` 值为 0

### 软删除

- 使用 `deleted_at` 字段实现软删除
- `deleted_at` 为 NULL 表示图片未删除
- `deleted_at` 有值表示图片已删除，记录删除时间
- 查询时需要过滤 `deleted_at IS NULL` 的记录

### 文件存储

- `url` 字段存储图片的相对路径
- 实际文件存储在服务器的 `./public/uploads/products/` 目录下
- 文件按年/月/日目录结构组织：`YYYY/MM/DD/filename`
- 文件名使用 UUID 确保唯一性

## API 接口支持

该表设计支持以下 API 操作：

1. **图片上传**: 单张或批量上传商品图片
2. **图片列表**: 获取指定商品的所有图片
3. **图片排序**: 更新图片的显示顺序
4. **图片删除**: 软删除指定图片

## 性能优化

### 查询优化

- 使用复合索引 `(product_id, sort)` 优化最常用的查询
- 软删除字段索引提高过滤性能

### 存储优化

- 图片文件按日期目录分散存储，避免单目录文件过多
- 使用相对路径存储，便于文件迁移

## 数据完整性

### 约束保证

- 外键约束确保图片必须关联有效的商品
- NOT NULL 约束确保必要字段不为空

### 级联操作

- 商品删除时自动删除相关图片记录
- 保持数据一致性

# 宏达服装进销存系统 (HD-PSI)

基于 Go + Vue 3 + Flutter 开发的服装行业进销存管理系统，采用前后端分离架构，专为男女装店铺设计的全流程管理解决方案，并提供移动端支持。

## 项目概述

HD-PSI 是宏达服装有限公司开发的进销存管理系统，支持多店铺管理、商品全生命周期追踪、智能库存预警、会员管理等功能，满足服装零售企业的日常运营需求。**项目包含一个基于 Flutter 开发的移动端应用，用于支持移动库存查询和扫码结账等功能。**

### 核心特点

- **多店铺管理**：支持男女装店铺独立核算，统一管理
- **商品全生命周期**：从采购、入库、销售到退换货的全流程追踪
- **智能库存管理**：基于品类和店铺的双重库存预警机制，支持周期性全盘/抽盘
- **会员数据分析**：记录会员体型数据、消费习惯，提供智能推荐
- **二维码管理**：基于 SKU + 批次的唯一加密二维码，支持防伪验证和销售扫码核验
- **移动端支持**：提供移动应用，支持库存查询和扫码结账等功能

## 技术栈

### 后端
- **语言框架**：Go 1.21 + Gin 1.9.1
- **数据库**：MySQL 8.0 + GORM 1.25.5
- **认证**：JWT 认证
- **API**：RESTful API
- **微服务**：独立的会员服务处理积分和推荐逻辑

### 前端
- **框架**：Vue 3 + Vite
- **UI 库**：Naive UI
- **HTTP 客户端**：Axios
- **路由**：Vue Router
- **状态管理**：Pinia

### 移动端
- **框架**：Flutter

## 功能模块

### 1. 库存管理
- ✅ 分店库存独立核算
- ✅ 品类库存分类预警
- ✅ 入库管理（采购/退货/调拨，自动识别目标店铺）
- ✅ 二维码生成与验证（基于SKU+采购批次生成唯一加密二维码，含校验码防伪）
- ✅ 出库管理（销售/换货/报损，记录操作店铺）
- ✅ 库存预警机制（按店铺和品类设置双重阈值）
- 🚧 库存盘点（支持周期性全盘/抽盘，分店铺执行）

### 2. 商品档案管理
- ✅ 基础属性管理（颜色/尺码/季节/品类）
- ✅ SKU 编码规则（品类(2)+年份(2)+季节(1)+颜色(3)+尺码(2)）
- ✅ 商品图片管理（支持多角度展示）
- ✅ 价格体系管理（成本价/吊牌价/促销价）
- ✅ 二维码字段（存储SKU+采购批次+校验码的Base64加密数据）

### 3. 采购管理
- ✅ 供应商管理（资质审核/评级体系，区分兰州/西安供应商）
- 🚧 采购订单流程（生成/审核/入库流程，自动关联货源城市）
- 🚧 到货验收（质检记录/差异处理）
- 🚧 货源追踪（采购批次与店铺库存自动关联）

### 4. 销售管理
- 🚧 零售终端集成（POS收银集成，带试衣间编号记录）
- 🚧 订单统一管理（线上线下订单统一处理）
- ✅ 移动扫码功能（支持手机扫描商品二维码自动带出商品档案）
- ✅ 价格同步机制（扫码后自动关联吊牌价并记录议价过程）
- ✅ 数据核验（销售时校验二维码有效性防止重复扫码）
- 🚧 议价日志（记录初始报价/最终成交价/议价次数）
- 🚧 试衣记录（顾客体型数据/试穿款式/满意度评分）
- 🚧 退换货流程（三包政策自动化）

### 5. 会员管理
- ✅ 顾客档案（体型数据/风格偏好/消费能力）
- ✅ 积分体系（消费1元=1积分，500分抵现10元）
- 🚧 消费历史（购买记录关联试衣数据和议价记录）
- 🚧 智能推荐（根据体型和偏好推荐搭配方案）

## 移动端应用

基于 Flutter 开发的移动端应用，旨在为店铺员工提供便捷的移动操作能力：
- **库存查询**：随时随地查询商品库存信息。
- **扫码结账**：通过扫描商品二维码快速完成销售结账。
- **其他功能**：未来计划集成更多功能，如移动盘点、会员信息查询等。

## 开发环境搭建

### 后端

1. 进入后端目录
```bash
cd backend
```

2. 安装依赖
```bash
go mod tidy
```

3. 运行后端服务
```bash
go run main.go
```

### 前端

1. 进入前端目录
```bash
cd fronted
```

2. 安装依赖
```bash
npm install
```

3. 运行开发服务器
```bash
npm run dev
```

4. 构建生产版本
```bash
npm run build
```

### 移动端

请参考 `mobile/README.md` 文件中的详细说明。

## API 文档

后端 API 遵循 RESTful 设计原则，主要包括以下资源：

- `/api/auth` - 认证相关
- `/api/products` - 商品管理
- `/api/suppliers` - 供应商管理
- `/api/inventory` - 库存管理
- `/api/purchases` - 采购管理
- `/api/sales` - 销售管理
- `/api/members` - 会员管理
- `/api/stores` - 店铺管理

详细 API 文档请参考后端代码或 Swagger 文档。

## 部署指南

### 集成部署（推荐）

将前端静态文件集成到后端服务中，只需要一个服务器即可运行完整系统。

1. 构建前端
```bash
cd fronted
npm run build
```

2. 将前端构建文件复制到后端的public目录

Windows环境：
```powershell
xcopy /E /Y fronted\dist\* backend\public\
```

Linux/Mac环境：
```bash
cp -r fronted/dist/* backend/public/
```

3. 构建并运行后端服务
```bash
cd backend
go build -o hd-psi-server
./hd-psi-server
```

4. 访问系统
浏览器访问：`http://localhost:8080`

### Docker 部署

1. 构建后端镜像
```bash
cd backend
docker build -t hd-psi-backend .
```

2. 构建前端镜像
```bash
cd fronted
docker build -t hd-psi-frontend .
```

3. 使用 Docker Compose 启动服务
```bash
docker-compose up -d
```

### 分离部署

1. 后端部署
```bash
cd backend
go build -o hd-psi-server
./hd-psi-server
```

2. 前端部署
```bash
cd fronted
npm run build
# 将 dist 目录部署到 Nginx 或其他 Web 服务器
```
